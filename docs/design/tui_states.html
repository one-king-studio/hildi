Anatomy of the shell

Four fixed regions, one flexible body. The header and status bar own the session identity and its consumption; the toolbar carries what the run is doing (left) and what the operator can do (right); the composer overlays the transcript so typing never reflows the messages.

Why only two hints

Every line here must name a key that actually does something from this screen. Ctrl+? lists commands was removed because no handler for it exists anywhere in the app — a hint is a promise, and a dead one is worse than none. This text is descriptive prose, so it is styled uniformly and keeps sentence case; it is not chrome.

Narrow panes: the label yields, never the hints

The label and the hints share one row. The hint budget is taken first — it is the fixed, known-length part — and the label takes what is left, clamped by display cells. At the extreme the label is dropped rather than clipped to a fragment. Before this rule, a long subject label silently squeezed the hints off the row and the text block clipped them mid-word, with nothing visibly broken enough to report.

Reasoning caption rotationpsThinking only

While the agent reasons, the caption rotates every 2.6 s: Thinking → Reasoning → Working it out → Considering → Pondering. The word is derived from the clock, not a per-frame counter, so a dropped frame cannot desynchronise it; and SetState resets the origin, so every turn starts on “Thinking”.

Only psThinking rotates. A tool run, an approval or an error states a fact and must not be decorated.

Long subjects are clamped, keeping the tail

48 display cells. The end of a path or command is what identifies it, so the tail is kept and the cut prefers a path separator — the result reads as a path rather than a chopped stem.

⠼ Editing …/widgets/TUIWidgetsChatPanel.pas ⠴ Running …-5 -- src/tui/widgets/TUIWid…

Malformed arguments still caption

Model output is attacker-influenced and often truncated mid-call. A parse failure must not break the status row — the tool is running. It falls back to the reason, then to the tool name.

Command paletteactionable entries only

Sidebar — the subagent listnot yet two-tone

Toggled with ctrl+d when the session has subagents. It takes the composer’s place and the composer’s chrome — same rounded box, same raised background, same lower-left info line and lower-right CTAs — with one deliberate difference: the border is amber, because this is not the prompt. It reads as “work in flight, not yours to type into”.

Each row is the child’s label plus its current turn title, so the list says what each agent is doing. The selected child loads into the stream; there is no prompt here, so the view is read-only.

Keys are chorded, not bare

ctrl+a / ctrl+r / ctrl+p, never a / r / p: bare letters are one stray keystroke from aborting or releasing a child that is mid-work, and the list has focus while a child streams — exactly when the operator is most likely to be typing at something else. Only the three chords are claimed, so no ordinary keypress is swallowed.

Current limitation. These CTAs are painted as one uniformly amber string. The two-tone rule (dim key, brighter action) is not applied here yet, though the shared splitter that would do it now exists.

Markdown rendering

Body text is a step dimmer than headings; bold and italic each carry a colour so emphasis survives terminals that ignore italic or map bold to a bright colour. Fenced code is a rounded box on the sunken surface with its language on the top-right of the top border.
