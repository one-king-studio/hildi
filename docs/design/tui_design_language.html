TUI Design Language v0 · first pass

Glyphs, motion, colour, and layout for the hildegard-helper terminal UI. Self-contained; no external assets.

Diagrams render in one monospace font with ligatures disabled and whitespace preserved. Box-drawing alignment needs a font that includes U+2500–U+257F (Menlo, DejaVu Sans Mono, JetBrains Mono, Cascadia Mono all do).

Markdown rendering

  
Model output in an assistant block. The body is a dim grey; bold is warm gold, italic is cyan, and bold italic is the cool cyan in bold — so emphasis stays visible even where a terminal ignores the italic rendition or maps bold to the bright colour. Headings use the bold gold. Inline code is violet on the sunken surface (a chip); links replace the colour; bold, italic, and strike only add weight.

Inline code and bullets

  
Inline code is violet on the sunken surface (233 #121212) — the same chip the fenced block uses, so the two read as code — which also keeps it clear of the bold gold. It is padded with one space each side, so the chip stands out from the words around it. The tan moves to the list bullets and ordered markers, where it reads as a marker rather than emphasis.

  

    
Inline code violet chip

      
140 #af87d7 on 233 #121212
here is inline code and bold and italic

    

    
Bullets tan

      
180 #d7af87   • item  1. item
a marker hue, no longer on code

    

  

  
Headings use the bold gold with the H1–H3 underline, so a heading is not confused with bold body text.


  
Tables

  
A GFM pipe table: a header row, a delimiter row that sets each column's alignment (:--- left, :---: centre, ---: right), then body rows — a thin ├─┼─┤ rule between every row, so the grid is closed. The table is sized to its content — it never stretches to fill the container — and only when the content is wider than the container are columns compressed and their cell text wrapped. Borders are the dim rule colour (240); the header is the bold gold; the body is the plain grey. Cells keep inline styling (bold, code, links).

  

  

  

    
Width policy least height

      
natural = widest cell in each column
chrome  = 3n + 1  (border + a space each side)

if sum(natural) <= avail:
    use natural          → narrower than the container
else:
    H = smallest per-row line budget where
        every cell fits the width
        (a column takes the smallest width
         that fits all its cells in H lines)
    spend any leftover on the line drops that
        shrink the tallest rows
    if the word floors overflow:
        squeeze the widest columns, break words;
        a table narrower than its borders is clipped

Turn stats

  
The status bar is session-cumulative, prefixed total so it is never mistaken for one loop's cost. Each successful loop ends with a dimmed divider carrying that loop's metrics, right-aligned with a single trailing rule — the same one-row shape as a collapsed thought or tool line. A thought block shows how long the model reasoned, from the same measured value live and on resume.

  

    
Transcript

      
> what changed in the pool?

 ─ Thought for 2.3s ────────────────────────────────── ▼ ─
  The pool caps concurrency, so I should read it first.

  The pool runs up to N commands at once and queues the rest.

 ───────────── 1.2k in · 310 out · 120 think · 92% cached · 3.4s · 2 req ─

      
The divider is dim (Muted), one row, stats right-aligned, one trailing ─. A failed or cancelled loop gets none.

    

    
Status bar

      
 ~/code/hildegard-helper   12.3M in · 127.3k out · 87% cached · 2h15m · 202 req

      
The workspace on the left; the session's consumption on the right (billed input, output, token-weighted cache hit, wall time, request count). The context lives on the header.

    

  

  

    
Format

      
header   id · ctx [shades] pct%
status   workspace · in · out · cached · time · req
divider  ─ … <stats> ─   (dim, one row)
thought  Thought for <duration>   (0 → "Thought")

    

    
Fields (unchanged from v1)

      
1.2k in · 310 out · 120 think · 92% cached · 3.4s · 2 req
        ^ in/out        ^ reasoning tokens   ^ cache hit
                          when present        ^ wall time  ^ requests

    

  






  
Session header

  
Session information moves onto the messages panel's top border: the session id at the left, the live session stats at the right. The status bar is then free for other purposes (currently left empty).

  

    
Header

      
╭ 4830c2f17d9c ────────────────── 121k [▓░░░░░░░░░] 12% ─╮
│                                                                             │
│  … the conversation …                                                       │
╰─────────────────────────────────────────────────────────────────────────────╯

      
The id is the first 12 hex, enough to --attach. The header carries only the context: the count, the bar (ten shade cells — a full ▓ per 10%, a ▒ half-cell at a 5% remainder, ░ background), and the percentage. The consumption is on the status bar.

    

    
Fields

      
id       first 12 hex
context  final context [shades] pct%

      
The session's consumption (in/out/cached/time/req) is on the status bar. Cost is omitted for now; it will be tracked per turn alongside the provider and model.

    

  






  
Tool streaming

  
A tool's output is a stream: a tool may flush chunks as it produces them and then complete with its authoritative result. While it runs the tool block is live — auto-expanded, showing only its tail — and when the result arrives it settles back to a collapsed line whose body is the result, so a resumed session renders the same thing.

  

    
While running

      
 ─ building ─────────────────────────────────── ▼ ─
  npm warn deprecated inflight@1.0.6
  added 214 packages in 8s
  > tsc -p .

      
Live: the block auto-expands and shows only the last few lines (LiveTailLines), so a long build never pushes the transcript around.

    

    
After completion

      
 ─ building ─────────────────────────────────── ▶ ─
  $ npm install && tsc -p .
  added 214 packages in 8s
  [exit 0]

      
Settled: collapsed, body replaced by the authoritative result (the shell transcript, capped at 32 KB) — identical to the resumed view. Only run_command streams today; the other tools are single-shot.
