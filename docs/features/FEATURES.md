# Features

Index of all features in hildegard-helper. Each feature lives in its own directory
under `docs/features/<Feature_Name>/` and follows the artifact chain described
in `../guidelines/spec-driven-development.md`:

`FEATURE.md` -> `<Component>_v1.SPEC.md` -> `<Component>_v1.TODO.md` -> `<Component>_v1.DONE.md`

## Status Key

- **Proposed** - `FEATURE.md` exists, no spec yet
- **Specified** - at least one `SPEC.md` exists
- **In Progress** - work is underway (a `TODO.md`, or code landed ahead of one)
- **Implemented** - all tasks done, `make check` green. A `DONE.md` is recorded
  when the feature had a `TODO.md`; a small feature that landed directly may
  have only `FEATURE.md` (noted in its row).
- **Parked** - decided against for now, or awaiting a need; the code (if any) is
  kept, not built
- **Superseded** - replaced by another feature; kept for history

| [Task List](Task_List/FEATURE.md) | Implemented | Task List v1 | A **long-lived, shared task list per workspace** — Trello-shaped work rather than a todo list one agent keeps in its head. Five statuses (`open`, `claimed`, `blocked`, `done`, `dropped`); claiming is a compare-and-swap, so two agents reaching for one card produce a visible conflict instead of silent duplicate work — the same discipline as hash-anchored writes, applied to work. **Status is not editable**: every transition is a verb with an actor, so the row answers *who moved this and why*; `task_done` from `open` is refused because the claim is the attribution. **Separate from the board on purpose**: a board entry is an append-only *fact*, a card's status is *mutable state*, and one table cannot hold both without losing one. The tail block shows a work queue (`mine` always, three `open`, blocks worth seeing) inside 400 bytes, reporting how many open cards exist while naming only three. Retention prunes finished cards by **count and age** and never a live one, nor any card another card names as its parent or blocker. **Six tools carry the ten verbs** — the five update verbs share `task_update`, the two moderate verbs share `task_moderate` with the gate applied per-verb — because the tools array is the largest recurring per-request cost. Deliberately **not a scheduler**: nobody is assigned, things are taken. `task_reassign` and `task_delete` are operator-gated; everything on your own claim is not. Test for the boundary: swap the agents for ten humans — if it still makes sense, it is a work list. |
